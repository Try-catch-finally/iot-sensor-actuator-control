# 协议设计文档

## 一、总体架构

```
┌──────────────┐      MQTT(WebSocket)       ┌─────────────────┐
│  Web 前端     │ ◄──────────────────────►  │  EMQX 服务器      │
│  (本工程)     │   订阅 usr/sensor          │  (地址见 .env)    │
└──────────────┘   发布 usr/actuator         └─────────────────┘
                                             │ 透传
                                      ┌──────┴──────┐
                                      │  Modbus 网关  │
                                      │  RTU 主站     │
                                      └──────┬──────┘
                          RS-485 ┌───────────┴──────────┐
                                 │ 从机 0x01 ~ 0x0F      │
                                 │ 传感器/执行器          │
                                 └───────────────────────┘
```

- 前端通过 **MQTT over WebSocket** 与网关双向通信
- 网关将 MQTT 载荷透传为 **Modbus RTU** 请求/响应
- 前端负责 Modbus RTU 帧的编解码（含 CRC16 校验）

## 二、Modbus RTU 帧格式

```
┌──────────┬──────────┬──────────────────┬──────────────┐
│ 从机地址  │ 功能码   │ 数据（可变长）     │ CRC16（2 字节）│
│ (1 字节)  │ (1 字节) │                  │ 低字节在前     │
└──────────┴──────────┴──────────────────┴──────────────┘
```

**CRC16-Modbus**：多项式 `0xA001`（反转 0x8005），初值 `0xFFFF`，低字节在前。

### 读请求（功能码 0x01~0x04）

```
从机地址  功能码  起始地址(高)  起始地址(低)  寄存器数(高)  寄存器数(低)  CRC16
 0x02     0x03     0x00         0x02         0x00         0x01       ...
```

例：光照传感器读命令 = `02030002000125F9`
（从机 0x02，功能码 0x03，起始 0x0002，1 个寄存器）

### 读响应

```
从机地址  功能码  字节数    数据...                CRC16
 0x02     0x03    0x02      0x03 0x37             ...
```

- 功能码 0x01/0x02：数据为线圈/离散输入位图，按位展开
- 功能码 0x03/0x04：数据为寄存器值（每寄存器 2 字节，大端）

### 写请求（功能码 0x05/0x06/0x0F/0x10）

| 功能码 | 含义 | 数据区 |
|---|---|---|
| 0x05 | 写单个线圈 | 地址(2) + 值(FF00=ON / 0000=OFF) |
| 0x06 | 写单个寄存器 | 地址(2) + 值(2) |
| 0x0F | 写多个线圈 | 地址(2) + 数量(2) + 字节数(1) + 数据 |
| 0x10 | 写多个寄存器 | 地址(2) + 数量(2) + 字节数(1) + 数据 |

写命令确认帧：**固定 8 字节**（回显请求的地址与值）。

### 异常响应

```
从机地址  功能码(最高位置1)  异常码   CRC16
 0x02     0x83               0x02     ...
```

异常码表：

| 异常码 | 含义 |
|---|---|
| 0x01 | 非法功能 |
| 0x02 | 非法数据地址 |
| 0x03 | 非法数据值 |
| 0x04 | 从机设备故障 |

## 三、帧长度规则与粘包处理

| 帧类型 | 长度 |
|---|---|
| 读响应 | `3 + 数据字节数 + 2` |
| 写确认（0x05/06/0F/10） | 固定 8 字节 |
| 异常响应 | 固定 5 字节 |

> MQTT 消息边界与 Modbus 帧边界**不对应**：一条 MQTT 消息可能包含多帧（粘包）或半帧（拆包）。

**解决方案**（`src/core/modbus.js` 的 `ModbusFrameDecoder`）：
1. 内部维护字节缓冲
2. 按帧长度规则尝试提取候选帧
3. 用 CRC16 校验候选帧，校验通过才输出
4. 校验失败则滑动丢弃 1 字节，重新定位帧边界

## 四、传感器数据格式

### 轮询请求去重

相同请求配置（从机 + 功能码 + 起始地址 + 数量）的传感器**共享一个轮询定时器**，避免重复发送相同命令。

### 默认加载的 4 个传感器

| 传感器 | 从机 | 功能码 | 起始地址 | 寄存器数 | 轮询间隔 | 值提取 |
|---|---|---|---|---|---|---|
| 光照传感器 | 0x02 | 0x03 | 0x0002 | 1 | 6s | 原始值（lux） |
| 温度传感器 | 0x03 | 0x03 | 0x0000 | 2 | 5s | 有符号16位 / 10（°C） |
| 湿度传感器 | 0x03 | 0x03 | 0x0000 | 2 | 5s | reg[0] / 10（%） |
| 噪声传感器 | 0x04 | 0x03 | 0x0006 | 1 | 7s | 原始值 / 10（dB） |

### 全部 15 个预设传感器

覆盖功能码 0x01（线圈）、0x02（离散输入）、0x03（保持寄存器）、0x04（输入寄存器），从机 0x02~0x0F。

> 值提取规则集中在 `src/entities/presets.js`，新增传感器类型只需添加配置与 `extractValue` 函数（开闭原则）。

## 五、执行器控制格式

### 全部 17 个预设执行器

覆盖写单个线圈（0x05）、写单个寄存器（0x06）、写多个寄存器（0x10），从机 0x01~0x08。

| 执行器 | 从机 | 功能码 | 起始地址 | 开关值 |
|---|---|---|---|---|
| 门锁 | 0x01 | 0x05 | 0x0000 | FF00 / 0000 |
| 报警灯 | 0x01 | 0x05 | 0x0001 | FF00 / 0000 |
| 风扇 | 0x01 | 0x05 | 0x0002 | FF00 / 0000 |
| LED灯 | 0x01 | 0x05 | 0x0003 | FF00 / 0000 |
| 电机 | 0x03 | 0x06 | 0x0001 | 0001 / 0000 |
| 步进电机 | 0x06 | 0x10 | 0x0000 | 0001 / 0000 |
| ... | ... | ... | ... | ... |

### 控制命令示例

```
开启门锁：05050000FF008DBE
关闭门锁：050500000000CC4E
```

## 六、数据流（前端内部）

```
MQTT 消息到达
   └→ ModbusFrameDecoder 拆帧（粘包/拆包/CRC 校验）
        └→ parseModbusRTU 解析（纯函数）
             ├→ 读响应  → SensorService.handleReadResponse → 提取值 → 事件通知 UI
             ├→ 写确认  → ActuatorService.handleWriteResponse → 更新状态 → 事件通知 UI
             └→ 异常    → SensorService.handleException → 卡片显示异常
```
